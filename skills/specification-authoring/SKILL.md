# Author a concise specification

Identify authoritative decisions, current behavior, desired outcome, constraints, and non-goals.
Separate approved facts from proposals and implementation observations.

Write only the detail needed for design, implementation, and verification:

- problem and user or system outcome;
- scope and non-goals;
- behavioral requirements and failure behavior;
- interfaces, compatibility, security, data, and operational constraints;
- observable acceptance criteria;
- risks and rollout or migration needs; and
- unresolved decisions with their impact.

Give requirements stable identifiers when the repository has an ID convention. Keep each normative
requirement independently verifiable. Do not silently choose product behavior, duplicate the design,
or expand the document into a project diary.
