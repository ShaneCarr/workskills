# Write a pull request description

Read the full diff and relevant work item. Explain the problem, meaningful solution, and why the
chosen shape fits the repository. Include material behavior changes, migration or rollout notes,
risks, and exact validation performed.

Do not paste a file-by-file changelog, claim tests that were not run, or hide limitations. Link the
work item using repository conventions. Keep screenshots or operational instructions only when
reviewers need them.
